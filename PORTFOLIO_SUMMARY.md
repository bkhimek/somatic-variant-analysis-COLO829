# COLO829 Tumour-Normal Somatic Genomics Pipeline — Project Summary

This document ties together a Nextflow-based cancer genomics pipeline built end to end over eight development phases, from initial research through a real result: automatically detecting and clinically interpreting three of a real melanoma cell line's actual, published driver mutations. It's written for anyone evaluating the project as a whole rather than reading through the phase-by-phase engineering notes in `docs/` — those stay available for anyone who wants the full detail behind any claim made here.

## What this pipeline does

The project implements GATK Mutect2-based tumour-normal somatic variant calling, benchmarked against a real published truth set for the COLO829/COLO829BL cell line pair (a widely used melanoma reference standard in cancer genomics), extended with CNVkit copy-number calling and an automated clinical-actionability interpretation layer built on the CIViC knowledgebase. Every stage runs as a containerized Nextflow DAG with two profiles — a fast development profile restricted to eight known melanoma driver genes, and a full whole-genome profile — so the same pipeline code scales from a laptop smoke test to a production-scale run without modification.

## What it actually proved

The result that matters most: run against real COLO829 sequencing data (extracted from ENA's public archive, not synthetic), the pipeline's Mutect2 output correctly identified three of COLO829's real, independently documented driver mutations — a BRAF V600E hotspot mutation, a CDKN2A frameshift deletion, and a TERT promoter mutation carrying the classic UV-damage signature — and every one of the pipeline's eight PASS-quality calls was independently confirmed as a true positive (zero false positives) against a separate published truth set. Those three findings were then cross-checked a second, independent way: against Cellosaurus and OncoKB's own published records of this exact cell line's genotype, confirming the pipeline's calls match real, external, pre-existing knowledge rather than an artifact of the pipeline itself. Finally, an automated interpretation layer built on CIViC's live clinical-evidence API correctly matched the BRAF V600E call to its real curated evidence base (132 real clinical evidence entries spanning melanoma, thyroid, and colorectal cancer contexts) entirely without human lookup — the same cross-reference that was originally done by hand, reproduced automatically.

## How the project got there

**Phase 0** resolved the open questions a project plan alone couldn't answer — which truth set genuinely fits COLO829 (a citation in the original plan pointed at the wrong cell line entirely), which container images and package names are real versus guessed, and which of two identically-labeled public sequencing accessions is actually the tumour versus the normal sample (resolved by cross-referencing an independent published paper that named the same accessions).

**Phase 1** built QC and alignment (FastQC/MultiQC, BWA-MEM2, duplicate marking). The real finding here was resource sizing: an initial guess that whole-genome alignment index-building would need about 19GB of RAM turned out to be off by roughly 4-6x — the real figure is 87-110GB, discovered by hitting out-of-memory failures at every size tried locally and finally building the index on a temporary high-memory cloud instance instead of continuing to guess. Three separate Nextflow version-compatibility breaks were also found and fixed by actually running the pipeline under the installed Nextflow version, not by reading changelogs.

**Phase 2** added contamination estimation and Mutect2 somatic calling. The standout finding: a single unsharded Mutect2 call against the whole genome doesn't fit any memory configuration this project's hardware offers, confirmed by both real out-of-memory crashes and Broad Institute's own GitHub issues reporting the same failure mode even at very large heap sizes. That limitation was later resolved properly (see below) rather than worked around.

**Phase 3** built benchmarking against the published truth set, and turned up two real problems that would have silently produced wrong results if not caught: first, the specific truth-set file the project plan named turned out to be corrupted at its source — a forensic byte-level investigation traced it to five unrelated files having been concatenated together in the public archive, with the real content never present, requiring a switch to a different (still real, still published) version of the same truth set. Second, the first benchmarking tool tried (hap.py) turned out to be architecturally the wrong tool for somatic variant comparison — it silently read every real variant as reference-matching because it expects a genotype field that somatic VCFs don't carry — caught by tracing an unexpected "0 haplotype blocks" result back to hap.py's own documentation, not by trial and error.

**Phase 4** added CNVkit copy-number calling, closing out with three real execution bugs: an output-file mismatch traced to CNVkit's own source code rather than assumed, and a Nextflow caching subtlety (a completed run's cached results can silently ignore a later code change to what files a step produces) that had to be understood before a fix could even be confirmed as working.

**Module 4 revisited**: the single-call Mutect2 limitation Phase 2 deferred was properly resolved by rebuilding it as a real interval scatter/gather architecture — splitting the genome into independent chunks, running Mutect2 on each in parallel, then merging the results back together — designed directly against GATK's own documentation, the Broad Institute's own production workflow, and an actively maintained open-source pipeline's real source code, rather than assumed from memory.

**The real-data milestone**: partway through this project, a review of the README's own wording surfaced a false assumption that had crept in — a claim that real full-depth sequencing data already existed from an earlier phase. Checking actual read counts on every file the project had produced proved this wrong; every BAM in the project was still a small development-scale subsample. Rather than let that stand, it was corrected transparently in the documentation, and a real path to genuine sequencing depth was found instead: the public archive hosting COLO829's real sequencing runs also hosts pre-aligned BAM files usable to extract real reads directly. A first extraction attempt run overnight unattended appeared to complete successfully but had in fact silently failed partway through — caught not by an error message, but by noticing the ratio of tumour-to-normal reads recovered didn't match the known real sequencing depth ratio for these samples. The fix — splitting one long fragile download into many small, independently retried ones — succeeded cleanly on the second attempt, and that real data is what produced every driver-mutation finding described above.

**Module 8** built the automated clinical-interpretation layer described above, choosing a live, freely accessible clinical evidence database after the originally planned commercial database's registration process turned out not to fit a personal research project. Every technical choice in this module — which specific software version to use, which reference database naming convention actually matches the project's existing reference genome, and the exact API structure of the live evidence database — was confirmed by direct testing against the real systems involved, not assumed from documentation, catching a real memory-crash bug and a real reference-genome-naming mismatch before either could produce a silently wrong result.

## What was deliberately not pursued, and why

A full whole-genome sequencing depth run (roughly 175GB of raw data plus a computationally expensive alignment step) was considered and explicitly declined in favor of the targeted real-data approach described above, after weighing the storage and compute cost against what it would add: the targeted approach already delivers real, externally verifiable driver-mutation findings, while a full-genome run's main additional value — genuine genome-wide copy-number signal and enough real variants to support mutational-signature analysis — was judged not worth the resource cost for this project's purposes. Mutational signature analysis (originally planned as a further phase) was set aside for the same reason: with only eight real variant calls recovered from the targeted extraction, that kind of statistical analysis would not produce a meaningful result no matter how correctly implemented, so building it now would demonstrate mechanics rather than science. CNVkit's copy-number output on the current real data is real code running correctly, but is not a real copy-number finding — coverage exists only over the extracted gene panel, so the tool's genome-wide segmentation is working across mostly-empty data by construction, and this is disclosed rather than glossed over in the project's own documentation.

## The engineering discipline behind the results

The pattern repeated across every phase of this project is worth naming directly, since it's arguably the more transferable skill than any single tool choice: nothing in this pipeline was accepted as correct because it looked plausible or matched a plan on paper. Container image tags were confirmed by actually pulling them, not guessed from naming conventions (two guessed tags across the project turned out not to exist). A truth-set file's integrity was confirmed by byte-level forensic analysis, not assumed from its filename. A benchmarking tool's suitability was confirmed by reading its actual behavior against real data, not assumed from its README. A silently truncated data download was caught by checking whether the numbers made biological sense, not by trusting a clean exit code. And when an assumption did turn out to be wrong — including one this project's own documentation stated confidently at one point — it was corrected openly, with the reasoning for the original mistake documented alongside the fix, rather than quietly rewritten as if it had never happened.
